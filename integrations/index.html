Integrating with AS400 and custom TMS systems without asking carriers to build much

Ram Yadlapalli · November 2026

Every carrier we deploy has a system of record, usually an AS400 or a TMS built in house, and an IT team with limited time for us. Connecting to that system is usually the hardest part of a deployment, which takes anywhere from 1 to 6 months. I have led every one since 2018.

Shipment data comes from the carrier's side, and plans and status updates have to go back. Rather than build something new for every carrier, I designed four patterns. During discovery we pick the one that suits the carrier's system and how much their team can take on.

Four ways data moves between the platform and a carrier's system.

PatternHow it worksWhen we use it
StreamingEvents flow continuously in both directions.The carrier can publish and consume events.
APIsOur APIs and theirs, called on demand or when something changes.The carrier has APIs, or can build a few.
FTP triggered flowsA file landing on FTP starts a flow that loads it, and files go back the same way.The system can only exchange files.
No client side integrationAn event on our side triggers an Azure Logic App that uploads files and writes data directly into the carrier's system.A small number of carriers with no IT resources to build an integration.

Streaming and APIs are the cleanest options when a carrier can support them. Some carriers can only exchange files, and the FTP triggered flow covers them.

The last pattern came from one or two carriers that had no IT resources to build an integration. Rather than wait, we changed our integration approach so we could onboard them. When something happens on our side, a Logic App uploads the files and writes the data into their system.

What carriers got

Carriers ended up with fewer routes and fewer miles, nearly zero missed appointments and 75% less planning time, and they moved to centralized planning and dispatching.
